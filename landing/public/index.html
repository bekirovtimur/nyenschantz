02 / БЫСТРЫЙ СТАРТ

От идеи до
первого запроса.

Ваш токен прокси, API-ключ провайдера
и доступная вам модель.

Два секрета — две задачи.

Для API нужен токен Nyenschantz от владельца сервера и отдельный API-ключ платформы. Адрес подключения: https://домен/YOUR_PROXY_TOKEN/платформа/.... В cURL-примерах токен задаётся переменной NYENSCHANTZ_TOKEN.

URL содержит секрет: не публикуйте его и не передавайте посторонним. Он может попасть в историю и логи клиента. Демонстрационные пользователи в users.json репозитория отключены; их токены не дают доступа. Страница не принимает и не сохраняет настоящие токены.

gemini.sh
curl "https://proxy.example.com/$NYENSCHANTZ_TOKEN/gemini/v1beta/models/$GEMINI_MODEL:generateContent" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"parts":[{"text":"Объясни SSE в двух предложениях"}]}]}'

Задайте NYENSCHANTZ_TOKEN, GEMINI_API_KEY и GEMINI_MODEL в окружении. Токен прокси выдаёт владелец сервера; модель выбирайте из каталога Gemini.

Ответ передаётся по мере поступления. Простой upstream дольше настроенного таймаута прерывает соединение.

◇

Ключи — на сервере.

Не публикуйте секреты во frontend-коде. Страница не запрашивает ключи и не отправляет тестовые API-запросы.

↗

Доверие имеет значение.

Оператор прокси технически имеет доступ к передаваемым данным. Используйте только доверенный сервер. WebSocket не поддерживается.
